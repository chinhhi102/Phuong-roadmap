# 📙 Phase 3 — Portfolio & Projects (Proof of Work)

> **Goal:** Produce a **complete, resume-worthy BA project** that proves you can do the job.
> **Est. time:** ~3–4 weeks · **Style:** heavily hands-on. You build real artifacts.

---

## 🎯 Why a portfolio wins jobs
Recruiters for junior BAs rarely see candidates with an actual **requirements package**. If you walk in with a full project — process maps, BRD, backlog, wireframes — you instantly look like someone who has *already done the job.*

> **Your advantage:** Use an **accounting/ERP scenario** (your domain!). Suggested project: *"Redesign the monthly invoice reconciliation & reporting process for a small business using an accounting system."* You'll sound like an expert because you are one.

---

## 🗂️ The project: end-to-end BA package

Work through these steps **in order** — each produces one portfolio artifact.

### Step 1 — Project vision & problem statement
- Define the business problem, goals, and success metrics.
- **Artifact:** 1-page **Project Vision / Business Case**.

### Step 2 — Stakeholder analysis & scope
- Identify stakeholders (owner, accountant, auditor, IT).
- Define what's **in scope / out of scope**.
- **Artifact:** Stakeholder map (power/interest) + **RACI** + scope statement.

### Step 3 — Elicitation plan (+ simulated interview)
- Plan which techniques you'd use and why.
- Write a set of **interview questions**; answer them as the "stakeholder" (role-play) to generate raw requirements.
- **Artifact:** Elicitation plan + interview notes.

### Step 4 — As-Is process map
- Model how reconciliation/reporting happens **today** (the manual, painful way).
- **Artifact:** **BPMN As-Is diagram**.

### Step 5 — To-Be process map
- Model the improved, streamlined future process.
- **Artifact:** **BPMN To-Be diagram** + a short "what changed & why" note.

### Step 6 — Business Requirements Document (BRD)
- Consolidate goals, scope, stakeholders, requirements, assumptions, constraints.
- **Artifact:** A professional **BRD** (use a template).

### Step 7 — Product backlog
- Break the solution into **epics → user stories** with **acceptance criteria** and **MoSCoW** priority.
- **Artifact:** Backlog in **Jira** (or a spreadsheet) — 1–2 epics, ~8–12 stories.

### Step 8 — Wireframes / prototype
- Design the key screens (e.g., reconciliation dashboard, exception list, report).
- **Artifact:** **Figma wireframes** (link).

### Step 9 — Data & report specifications
- Draw an **ERD** for the relevant data; write **SQL** for at least one report; specify report fields & rules.
- **Artifact:** ERD + report spec + sample SQL.

### Step 10 — Package & present
- Assemble everything into a clean case study (Notion page, PDF, or GitHub repo).
- Write a **1-page executive summary** + record a **5-min walkthrough** (optional but powerful).
- **Artifact:** Published portfolio project + summary.

## 📦 Final portfolio checklist
- [ ] Project Vision / Business Case
- [ ] Stakeholder map + RACI + scope
- [ ] Elicitation plan + interview notes
- [ ] BPMN As-Is diagram
- [ ] BPMN To-Be diagram
- [ ] BRD document
- [ ] Product backlog (epics + user stories + acceptance criteria + MoSCoW)
- [ ] Figma wireframes
- [ ] ERD + report spec + SQL
- [ ] Executive summary + published case study

## 💡 Where to host your portfolio
- **Notion** (easiest, looks clean, shareable link)
- **GitHub** (a repo with a well-written README + linked artifacts — great for IT BA roles)
- **PDF** case study (attach to job applications)

> **Stretch goal:** Do a *second, smaller* project in a **different domain** (e.g., e-commerce order returns) to show range. Two projects >> one.
